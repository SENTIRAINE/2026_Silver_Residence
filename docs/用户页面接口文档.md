## 1. 页面范围

当前用户页已经收缩为最小版本，只保留 4 个核心部分：

- 地图服务预留容器 `#mapContainer`
- 顶部搜索栏
- 个人中心入口
- 可收起到右侧边栏的 AI 对话框

已经移除：

- 市场动态
- 购房指南
- 示例房源卡片
- 地图价格标记点
- 收藏、消息、咨询等额外入口

## 2. 当前已实现接口

### 2.1 登录

- 方法：`POST`
- 路径：`/user/login`
- 用途：登录成功后进入用户页面
- 请求体：

```json
{
  "username": "zhangsan",
  "password": "123456"
}
```

### 2.2 退出登录

- 方法：`POST`
- 路径：`/user/logout`
- 用途：后续个人中心页可直接复用

### 2.3 AI 对话

- 方法：`POST`
- 路径：`/ai/chat`
- `Content-Type`：`text/plain;charset=UTF-8`
- 返回类型：`text/event-stream`
- 当前前端用途：
  - 搜索栏提交自然语言需求
  - 对话框输入自然语言需求

请求示例：

```text
帮我筛选 200 万以内、距离三甲医院 1 公里内的养老社区
```

## 3. 当前前端事件

除了 HTTP 接口，页面还发出一个前端事件，方便后续接入地图 agent：

### 3.1 agent-map-filter-request

- 触发位置：
  - 搜索栏点击“搜索”
  - 对话框点击“发送”
- 事件名：`agent-map-filter-request`
- 事件载荷：

```json
{
  "source": "search",
  "text": "帮我筛选 200 万以内、距离医院近的房源"
}
```

说明：

- 当前只是 `window.dispatchEvent(new CustomEvent(...))`
- 后续可由地图模块监听这个事件，调用 agent 解析条件，再刷新点要素图层

## 4. 建议新增接口

为了实现“agent 筛选地图要素 -> 展示符合条件的点要素”，建议后端补以下最小接口。

### 4.1 获取地图配置

- 方法：`GET`
- 路径：`/api/map/config`
- 用途：前端初始化 GeoScene 地图和图层

返回示例：

```json
{
  "portalUrl": "https://your-portal.example.com/portal",
  "webMapId": "xxxxxxxxxxxxxxxxxxxx",
  "featureLayerUrl": "https://your-server.example.com/server/rest/services/养老社区/FeatureServer/0",
  "defaultCenter": [116.391, 39.907],
  "defaultZoom": 11
}
```

### 4.2 获取可筛选字段元数据

- 方法：`GET`
- 路径：`/api/map/filter-schema`
- 用途：让 agent 知道哪些字段可筛选、字段类型是什么、哪些值可枚举

返回示例：

```json
{
  "layerName": "养老社区点位",
  "fields": [
    {
      "name": "price_total",
      "label": "总价",
      "type": "number",
      "operators": ["<=", ">=", "between"]
    },
    {
      "name": "elevator",
      "label": "是否电梯房",
      "type": "boolean",
      "operators": ["="]
    },
    {
      "name": "district",
      "label": "行政区",
      "type": "string",
      "operators": ["=", "in", "like"]
    }
  ]
}
```

### 4.3 agent 条件解析接口

- 方法：`POST`
- 路径：`/api/agent/map-filter`
- 用途：把自然语言需求解析成结构化筛选条件

请求示例：

```json
{
  "text": "帮我筛选 200 万以内、朝阳区、距离三甲医院 1 公里内的养老社区",
  "context": {
    "city": "北京"
  }
}
```

返回示例：

```json
{
  "intent": "filter_map_points",
  "filters": [
    {
      "field": "price_total",
      "operator": "<=",
      "value": 2000000
    },
    {
      "field": "district",
      "operator": "=",
      "value": "朝阳区"
    },
    {
      "field": "hospital_distance",
      "operator": "<=",
      "value": 1000
    }
  ],
  "keywords": ["养老社区"],
  "explanation": "已识别为价格、行政区和医疗距离联合筛选"
}
```

### 4.4 执行地图要素查询接口

- 方法：`POST`
- 路径：`/api/map/query-features`
- 用途：根据结构化条件查询 GeoScene 要素服务，并返回点要素

请求示例：

```json
{
  "where": "price_total <= 2000000 AND district = '朝阳区' AND hospital_distance <= 1000",
  "outFields": ["objectid", "name", "price_total", "district", "longitude", "latitude"],
  "returnGeometry": true,
  "resultRecordCount": 200
}
```

返回示例：

```json
{
  "total": 12,
  "features": [
    {
      "attributes": {
        "objectid": 1,
        "name": "朝阳颐养中心",
        "price_total": 1860000,
        "district": "朝阳区"
      },
      "geometry": {
        "x": 116.48,
        "y": 39.92
      }
    }
  ]
}
```

### 4.5 保存查询历史

- 方法：`POST`
- 路径：`/api/map/query-history`
- 用途：记录用户筛选历史，便于回放和推荐

## 5. 前端推荐调用链路

建议后续按下面顺序接入：

1. 用户在搜索栏或对话框输入自然语言需求。
2. 前端触发 `agent-map-filter-request`。
3. 前端或后端调用 `/api/agent/map-filter`，把自然语言转成结构化条件。
4. 后端把结构化条件转换为 GeoScene 要素查询语句。
5. 后端调用 GeoScene 要素服务，或前端直接用 `FeatureLayer.queryFeatures()` 查询。
6. 前端将返回的点要素加载到地图，并缩放到结果范围。

## 6. GeoScene + Agent 搭建步骤

下面步骤是针对“GeoScene Pro 发布地图服务，前端用 GeoScene JS API，agent 负责自然语言筛选”的推荐实施顺序。

### 6.1 在 GeoScene Pro 整理点要素数据

目标：

- 确保养老社区、医院、地铁站等图层字段规范
- 提前准备适合筛选的字段

建议至少保留这些字段：

- `name`
- `district`
- `price_total`
- `elevator`
- `barrier_free`
- `hospital_distance`
- `subway_distance`
- `elder_score`
- `longitude`
- `latitude`

原因：

- agent 最终只能把自然语言映射到“字段 + 运算符 + 值”
- 字段越规整，后续条件解析越稳定

### 6.2 在 GeoScene Pro 发布可查询的要素服务

推荐发布类型：

- 优先：可查询的要素图层 / 要素服务
- 可选：地图服务中的可查询子图层

不建议只发纯底图切片，因为：

- agent 需要筛选点要素
- 点要素筛选依赖属性查询和几何返回

实施建议：

1. 在 GeoScene Pro 准备好地图和点要素图层。
2. 通过共享 Web 图层流程发布到 GeoScene Online 或 GeoScene Enterprise。
3. 确保发布结果支持属性查询、返回几何、按字段过滤。
4. 记录服务 URL、图层 ID、门户 `webMapId`。

说明：

- 这一步的具体菜单名称会随 GeoScene Pro 版本略有差异。
- 但从前端接入角度，最终你需要的是 `WebMap` 或 `FeatureLayer` 可访问地址。

### 6.3 在门户中组织 WebMap

推荐做法：

1. 在 GeoScene 门户中创建 WebMap。
2. 把底图、养老社区点位、医院、地铁等图层组织进去。
3. 设置默认范围、默认图层可见性和弹窗字段。
4. 记录 `webMapId`。

好处：

- 前端直接按 `webMapId` 加载
- 后续切图层、改样式、换默认范围不必频繁改代码

### 6.4 前端接入 GeoScene JS API

前端最小实现建议：

1. 在 `#mapContainer` 挂载 `MapView`。
2. 先加载 `WebMap`，再按需要拿到业务图层。
3. 将结果图层保存为单独变量，便于后续更新筛选条件。

可选两种方式：

- 方式 A：直接加载 `WebMap`
- 方式 B：直接加载 `FeatureLayer`

### 6.5 搭建 agent 的最小能力

agent 不要一开始就直接碰地图 SDK，先只做“条件理解”。

建议拆成两个阶段：

#### 阶段一：自然语言转结构化条件

输入：

- `帮我找朝阳区 200 万以内、距离医院近的养老社区`

输出：

```json
{
  "district": "朝阳区",
  "price_total_lte": 2000000,
  "hospital_distance_lte": 1000,
  "category": "养老社区"
}
```

#### 阶段二：结构化条件转查询语句

把结构化条件映射成：

- GeoScene 要素服务 `where` 条件
- 或 `queryFeatures()` 参数

例如：

```text
district = '朝阳区' AND price_total <= 2000000 AND hospital_distance <= 1000
```

### 6.6 agent 服务端推荐结构

推荐按下面 4 层拆开：

1. `Prompt 层`
   负责把用户自然语言整理成稳定的解析提示词。
2. `Schema 层`
   从 `/api/map/filter-schema` 提供可筛选字段白名单。
3. `Planner 层`
   把自然语言解析成结构化 JSON。
4. `Executor 层`
   把 JSON 转成 `where` 并查询 GeoScene 图层服务。

这样做的好处：

- 避免 agent 直接生成危险 SQL
- 字段名、运算符都能受控
- 后续容易加审计、缓存和回放

### 6.7 地图渲染结果

拿到符合条件的要素后，前端建议做 3 件事：

1. 清空旧结果图层。
2. 加载新点要素或设置图层过滤条件。
3. 自动缩放到结果范围。

常用做法：

- 结果少：前端用 `GraphicsLayer` 临时绘制
- 结果多：直接给 `FeatureLayer` 设置过滤表达式

### 6.8 先做 MVP，不要一步到位

第一版只做这几个条件就够了：

- 行政区
- 总价
- 是否电梯房
- 医院距离
- 地铁距离

先把这 5 个字段打通，再逐步增加：

- 适老化评分
- 无障碍改造
- 配餐服务
- 康复设施
